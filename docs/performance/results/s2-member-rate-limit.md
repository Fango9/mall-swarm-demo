# S2 会员维度限流结果

## 1. 执行信息

- 批次：`perf13-20260830-001`
- 执行时间：`2026-08-30 15:53:51 CST`
- 工具：k6 `v1.7.1`
- 入口：`http://127.0.0.1:8088`（Nginx → Gateway → Portal）
- 请求接口：`GET /portal/cart/items`
- 鉴权：12 个专用 MEMBER 各自通过 `/auth/login` 获取真实 Bearer Token
- 分桶方式：Gateway 根据 Token 解析出的 `memberId` 分桶
- Gateway 配置：补充速率 `5/s`，突发容量 `10`
- 压测参数：12 VU；每个 VU 固定对应一个会员并连续请求 20 次

## 2. 实测结果

| 分类 | 请求数 | 说明 |
| --- | ---: | --- |
| 会员登录成功 | 12 | 12 个专用账号均获得真实 MEMBER Token |
| 购物车业务成功 | 120 | HTTP `200` 且业务 `code=200` |
| Gateway 限流 | 120 | HTTP `429`、业务 `code=42901`、提示语为“请求过于频繁，请稍后再试” |
| 认证/授权失败 | 0 | 未发生 |
| 其他业务错误 | 0 | 未发生 |
| 系统错误 | 0 | 未发生 |

- HTTP 总请求数：`252`（12 次登录 + 240 次购物车读取）
- 购物车读取分类总和：`240`（120 成功 + 120 限流）
- 检查通过率：`100%`（264/264）
- p95 延迟：`24.26 ms`
- p99 延迟：`60.82 ms`

## 3. 隔离与数据安全证据

每个会员的最后一次迭代都检查“该会员同时出现过放行和限流”；12 项逐会员检查均通过。因此，限流不是由本机/Nginx 的单一来源 IP 共享触发，而是按各自 `memberId` 独立生效。

压测前后均核验：12 个专用 MEMBER 各自仅有一条专用 SKU 购物车项，数量均为 1。该实验只读访问购物车，没有创建订单、修改购物车、扣减库存或新增预占记录。

k6 的 `http_req_failed` 约为 `47.6%`，仅表示它将 120 个 HTTP 429 归为非 2xx；业务分类检查全部通过，不代表系统错误。
