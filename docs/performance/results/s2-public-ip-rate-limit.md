# S2 公开浏览 IP 限流结果

## 1. 执行信息

- 批次：`perf13-20260830-001`
- 执行时间：`2026-08-30 15:44:12 CST`
- 工具：k6 `v1.7.1`
- 入口：`http://127.0.0.1:8088`（Nginx → Gateway → Portal）
- 请求接口：`GET /portal/products/<专用商品 ID>`
- 分桶方式：Gateway 从实际远端地址取得客户端 IP；本机请求经同一个 Nginx 入口，属于固定 IP 分桶
- Gateway 配置：补充速率 `20/s`，突发容量 `40`
- 压测参数：固定到达速率 `60 req/s`，持续 `4s`，预分配 10 VU，最大 20 VU

## 3. 结论

在单一 Nginx 来源 IP、请求速率明显高于配置阈值的条件下，Gateway 同时产生了放行请求和限流请求，证明 IP 维度 Redis 令牌桶已实际生效。

k6 的 `http_req_failed` 为约 `50.2%`，其原因是 k6 默认将 HTTP 429 计为非 2xx；这不表示系统错误。本场景的业务分类检查为 `100%` 通过，且 429 响应符合项目统一 JSON 响应约定。
