# 流程 14：SLO 与停止条件

## 1. 浏览与搜索

- 错误率小于 1%；
- p95 小于 500 ms；
- p99 和延迟趋势不得持续恶化。

适用场景：P1、P2、P3、P6。

## 2. 购物车与下单

- 错误率小于 1%；
- p95 小于 1,500 ms；
- 库存不足、受控限流等预期业务拒绝必须单独统计，不计入技术错误率；
- 不得出现库存超卖、重复订单、Outbox 与消费不一致。

适用场景：P4、P5。

P5 每轮必须核对：

成功订单数 = CONFIRMED 预占数 = 已消费 ORDER_CREATED 事件数 = Redis 库存投影变化量 = MySQL lock_stock 变化量

## 3. 全场景健康要求

- RabbitMQ Ready、Unacked、DLQ 不得持续增长；
- 不得出现容器 OOM、连接池耗尽、严重 MySQL 锁等待或频繁 Full GC；
- 记录 k6、Docker、JVM、MySQL、Redis、RabbitMQ 与 Elasticsearch 指标。

## 4. 停止条件

满足任一条件即停止继续加压，并保留现场证据：

1. 同一 SLO 连续两个阶段失败；
2. 核心资源达到不可恢复饱和；
3. 发现库存、订单、Outbox 或消费不一致；
4. 发现非 `PERF14-` 数据受到影响；
5. 发生数据损坏。

## 5. 单机限制

若 k6 与应用运行在同一台机器，结果必须标记为“单机下限基线”。它受压测机与被测系统争用 CPU、内存和网络资源影响，不能外推为生产容量。
